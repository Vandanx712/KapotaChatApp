## 2. SIX CORE MOBILE ENGINEERING PILLARS (MANDATORY STANDARDS)

### Pillar 1: High-Performance Rendering
- **Virtualization Engine**: Use `@shopify/flash-list` (or `legend-list`) for ALL lists (Conversations, Chat Messages, Group Members, Post Sharing Picker, Comments, Contacts, Post Grids). Never use raw unoptimized `FlatList` or `ScrollView`.
- **Zero Render Cascades**: Wrap all list items and reusable components in `React.memo` with strict custom equality comparisons or stable primitive props.
- **Stable References**: Every callback passed down props MUST use `useCallback`. Every transformed object/array MUST use `useMemo`.
- **Isolated Leaf State**: Rapidly updating state (audio playback scrubbers, typing indicators, upload/download progress bars, video timers) must be strictly isolated inside dedicated leaf components so the parent screen or message list never re-renders during playback/typing.

### Pillar 2: Native Gestures (RNGH v2 API)
- Utilize `react-native-gesture-handler` v2 (`Gesture.Pan()`, `Gesture.Tap()`, `Gesture.LongPress()`, `Gesture.Pinch()`) with `react-native-reanimated` (v3+).
- **Swipe-to-Reply**: WhatsApp-style left/right swipe on message bubbles with elastic spring resistance, haptic feedback trigger, and smooth reply bar reveal.
- **Double-Tap to Like**: Instagram-style double-tap gesture on Explore reels and post images with an animated floating, scaling, and fading heart icon.
- **Contextual Action Sheets**: Long-press on message bubbles to present an iOS/Material floating reaction emoji picker and action sheet (Reply, Copy Text, Edit, Forward, Star, Delete for Me, Delete for Everyone).
- **Interactive Bottom Sheets**: Use `@gorhom/bottom-sheet` for Comments, Share dialogs, Attachment pickers, Media info, and Settings modals with fluid spring physics.

### Pillar 3: Performance & Memory Management
- **Reel / Video Feed Memory Recycling**: In the Explore feed, strictly recycle video components. ONLY the currently visible active video plays. Off-screen videos must immediately pause, detach players, and free hardware decoders to prevent Out-Of-Memory (OOM) crashes.
- **Optimized Image Pipeline**: Use `react-native-fast-image` or `expo-image` with aggressive disk caching, priority queues, and blurhash / color placeholder backgrounds.
- **Audio Stream Buffering**: Lightweight background streaming audio manager with waveform rendering and 1.5x / 2x speed multipliers.
- **Hermes JS Optimization**: Ensure all data structures and transforms are optimized for the Hermes engine.

### Pillar 4: Navigation Lifecycle & Focus Handling
- **React Navigation**: Use `@react-navigation/native-stack` for smooth native transitions and `@react-navigation/bottom-tabs` for the main shell.
- **Lifecycle Cleanups with `useFocusEffect` & `useIsFocused`**:
  - Immediately pause video playback and audio when navigating away or switching tabs.
  - Deactivate camera hardware session (`react-native-vision-camera` / `expo-camera`) when the scanner or camera screen loses focus to conserve battery.
- **Android Hardware Back Handling**: Pressing hardware back must close open bottom sheets, image viewers, and modals in reverse order before navigating back or exiting.

### Pillar 5: Platform-Specific Behavior (iOS vs Android)
- **iOS Implementation**:
  - Glassmorphic translucent blur headers and toolbars using `@react-native-community/blur` or `expo-blur`.
  - Native haptic feedback using `react-native-haptic-feedback` on message long-press, swipe-to-reply trigger, and double-tap like.
  - Safe Area insets (`react-native-safe-area-context`) accounting for Dynamic Island, Notch, and Home Indicator bar.
  - Natural iOS momentum scrolling with bounce physics.
- **Android Implementation**:
  - Material 3 fluid ripples on all touchables (`Pressable` with `android_ripple={{ color: 'rgba(255,255,255,0.08)' }}`).
  - Edge-to-edge transparent status bar and gesture navigation bar.
  - Android 13+ Scoped Storage and runtime permissions (`READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO`, `READ_MEDIA_AUDIO`, `POST_NOTIFICATIONS`).

### Pillar 6: Native Constraints
- **Keyboard Handling**: Zero-jump, jitter-free Keyboard Accessory View for chat inputs using `react-native-keyboard-controller` or `react-native-keyboard-aware-scroll-view`.
- **Foreground & Background File Transfers**: Resumable file downloads using `react-native-fs` or `react-native-blob-util` streaming directly to disk.

## 3. COMPREHENSIVE KEY FEATURE SPECIFICATIONS & UI/UX FLOWS

### A. Authentication, Email Verification, Password Recovery & Linked Devices
- **Mobile Sign Up Flow (2-Step Email Verification)**:
  - **Step 1: Account Information & Geolocation**:
    - User inputs Full Name, Email address, Password (min 6 characters with live strength meter), Gender (`male` / `female` / `other`).
    - Obtains device GPS coordinates (`location: { lat, lng }`) via `@react-native-community/geolocation` or `expo-location` (required for proximity & local experiences).
    - User presses "Continue / Request Code".
    - Calls `POST /api/auth/signup/request-otp` with `{ fullname, email, password, gender, location }`.
    - Server verifies email uniqueness and sends a 6-digit OTP to the user's email.
  - **Step 2: 6-Digit Email Verification Screen**:
    - Seamlessly transitions to the Email Verification step with a clean 6-digit pin input (`inputMode="numeric"`, auto-focus, paste OTP support).
    - Countdown timer (60s) with "Resend verification code" button calling `POST /api/auth/signup/request-otp`.
    - "Edit signup details" link allowing user to correct typos in their email or name.
    - User submits 6-digit OTP.
    - Calls `POST /api/auth/signup/verify` with `{ fullname, email, password, gender, location, otp }`.
    - On success: MongoDB account is created, JWT tokens are issued, user is authenticated into global state, and navigated directly to the main app!
- **Mobile Login Flow**:
  - Email and Password with smooth floating labels (`POST /api/auth/login`).
  - Biometric quick-unlock (FaceID / Fingerprint) using `react-native-keychain` / `expo-local-authentication`.
  - **CRITICAL**: Do NOT display a QR Code on the mobile login screen. QR Code display is strictly for Web desktop login (`/login` on desktop browsers).
- **Forgot Password Flow**:
  - Step 1: User enters email $\rightarrow$ Calls `POST /api/auth/forgot-password/request-otp`.
  - Step 2: 6-digit OTP verification screen with countdown resend timer.
  - Step 3: Enter new password and confirm $\rightarrow$ Calls `POST /api/auth/forgot-password/verify` with `{ email, otp, newPassword }`.
- **Linked Devices Feature (WhatsApp Style)**:
  - Settings -> **Linked Devices** screen (`GET /api/auth/sessions`):
    - Displays all active web desktop sessions with OS, browser, IP address, network, and last active timestamp.
    - Individual remote logout (`DELETE /api/auth/sessions/:id`) and "Log out from all other devices" (`DELETE /api/auth/sessions/others`).
  - Large **"Link a Device"** primary action button:
    - Opens native camera scanner (`react-native-vision-camera` or `expo-camera`).
    - Pointing at the QR code on the Kapota Web Login page parses the `qrToken`.
    - Calls `POST /api/auth/qr-login/scan` with `{ qrToken }`.
    - Prompts instant biometric confirmation ("Confirm linking Web session") and calls `POST /api/auth/qr-login/complete` to log the web desktop in immediately!

  - **iOS**: `Documents/Kapota Media/`
- **Auto-Download Logic**:
  - Connected to backend API `PUT /api/user/media-settings` and `authUser.mediaSettings`:
    - `autoDownload`: Boolean (True / False)
    - `maxAutoDownloadBytes`: Number (e.g. 10MB default)
  - When a message with media arrives:
    - If `autoDownload === true` AND `media.bytes <= maxAutoDownloadBytes` $\rightarrow$ automatically download in background and save to local folder.
    - If `autoDownload === false` OR `media.bytes > maxAutoDownloadBytes` $\rightarrow$ show blurred thumbnail with circular download arrow button and file size badge (e.g. "⬇ 14 MB").
- **Sender-Side Instant Caching**:
  - When the sender picks a file from gallery/camera to send, instantly copy it into `Kapota/Media/` so the sender never has to download their own media.
- **Media Cache Cleanup (Feature 2 & 3)**:
  - When a message is deleted for everyone or deleted for the user, purge the local file from disk.
  - When a chat is cleared, bulk delete all associated local files.
